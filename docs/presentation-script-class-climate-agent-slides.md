## สไลด์ที่ 2: Pain Point

### สิ่งที่แสดงบนสไลด์
- ภาพห้องเรียน / นักเรียน / ครู
- ข้อความสั้น:
  - `ครูเห็นปัญหาช้า`
  - `นักเรียนไม่กล้าพูดตรง ๆ`
  - `ข้อมูลดิบเสี่ยงต่อความเป็นส่วนตัว`

### สคริปต์คำบรรยาย
> ปัญหาหลักของการดูแลบรรยากาศในห้องเรียนคือ ครูอาจไม่เห็นสัญญาณเตือนตั้งแต่เนิ่น ๆ เช่น นักเรียนเริ่มเครียด เหนื่อย หรือรู้สึกว่าไม่เป็นธรรม  
> อีกด้านหนึ่ง นักเรียนหลายคนอาจไม่กล้าพูดตรง ๆ ต่อหน้าครู และถ้าเปิด feedback แบบดิบทั้งหมดก็อาจกระทบความเป็นส่วนตัวของนักเรียนได้  
> ดังนั้นจึงจำเป็นต้องมีระบบ AI เข้ามาช่วยสรุปข้อมูลแบบปลอดภัย มองเห็นแนวโน้มได้เร็วขึ้น และยังให้ครูเป็นผู้ตัดสินใจขั้นสุดท้ายครับ

## สไลด์ที่ 6: Demo - Recommendation / Approval / Loop Closure

### สิ่งที่แสดงบนสไลด์
- การ์ด recommendation
- ปุ่ม approve / dismiss
- ผลลัพธ์หลังครูตอบสนอง

### สคริปต์คำบรรยาย

> ระบบจะสร้าง recommendation draft ให้ครูตรวจสอบก่อนเสมอ แล้วครูเป็นผู้ approve หรือ dismiss ด้วยตัวเอง  
> เมื่อครูตอบสนองแล้ว ระบบจะปิด loop กลับไปยังฝั่งนักเรียน ทำให้ feedback ทั้งหมดมีการตอบกลับอย่างเป็นระบบครับ

## สไลด์ที่ 7: Architecture & Process Review

### สิ่งที่แสดงบนสไลด์
- Mermaid block diagram หรือกล่องลูกศร
- โหมด `Preprocessing Mode`
- โหมด `Processing Mode`
- โค้ดบรรทัดสั้น ๆ:

```text
Apply migrations, provision demo auth, then load supabase/seed/presentation-dataset.sql.
```

### สคริปต์คำบรรยาย
> สถาปัตยกรรมของระบบถูกแบ่งเป็น 2 โหมดหลัก คือ **Preprocessing Mode** และ **Processing Mode** ครับ  
> ฝั่ง Preprocessing เริ่มจากข้อมูลที่นักเรียนส่งเข้ามาผ่านหน้า Next.js frontend แล้วส่งต่อไปยัง Supabase เพื่อเก็บข้อมูลและสรุปแบบ aggregate โดยมี privacy guard ควบคุมอยู่  
> ก่อนใช้เดโมจริง เราจะ apply migrations ก่อน จากนั้น provision บัญชี demo auth ให้ password login ใช้งานได้จริง แล้วจึงรัน `supabase/seed/presentation-dataset.sql` เพื่อโหลดข้อมูลตัวอย่างเข้า Supabase/Postgres ให้พร้อมใช้งานครับ  
> ส่วน Processing Mode จะให้ n8n ทำหน้าที่เป็น workflow orchestrator เรียกข้อมูลที่เตรียมไว้แล้วไปวิเคราะห์ และให้ LLM ช่วยสร้าง recommendation draft ก่อนให้ครู approve ทุก action ครับ
